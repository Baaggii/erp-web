## 3 GitHub Actions auto‑deploy (already set up)

```yaml
name: Deploy ERP to VPS
on:
  push:
    branches: [ master ]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: appleboy/ssh-action@v1
        with:
          host:       ${{ secrets.SSH_HOST }}
          port:       ${{ secrets.SSH_PORT }}
          username:   ${{ secrets.SSH_USER }}
          key:        ${{ secrets.SSH_KEY }}
          passphrase: ${{ secrets.SSH_PASSPHRASE }}        # omit if key has no passphrase
          script: |
            export NODE_OPTIONS=--openssl-legacy-provider
            cd ~/apps/erp-web
            git pull --rebase origin master
            npm install --omit=dev         # or `npm ci` if lock‑file in sync
            npm run build
            pm2 reload erp-web || pm2 serve build 3000 -f --spa --name erp-web
```

Secrets (`Settings → Secrets & Vars`): `SSH_HOST`, `SSH_PORT`, `SSH_USER`, `SSH_KEY`, `SSH_PASSPHRASE`.

## 6 Database Database

### Canonical script

* **File:** `db/schema.sql` (version‑controlled in the repo)
* **Generated from:** `mmaddin1.xlsm` sheets using rule **row 7 = 1  AND  row 2 ≠ "S"**, columns trimmed at `PRINT | LOCATION`.
* **Current tag:** `schema_v4` (25 Apr 2025).

First deploy (optional):
```bash
mysql -u$DB_USER -p$DB_PASS $DB_NAME < db/schema.sql
```

### Migration policy

1. Add ALTERs to `schema.sql` (or new migration files).
2. Bump semantic tag → `v5`, `v6` …
3. Commit & push – CI will apply via Flyway / simple `mysql <` step.

### Audit strategy

*Transaction tables* keep a single `status` ENUM (`draft / confirmed / edited / deleted`).
Detailed history (who/when/why) lives in **audit_logs** trigger‑based table. Legacy `*num` columns retained until data import is validated, then dropped.

### Dynamic form metadata (`form_fields`)
Holds UI‑generation rules so a single form can pull multiple lookups. Any field not used in a transaction simply stores **NULL / 0 / ''** as per `data_type`.

| Column        | Type & constraints                                             | Notes                                   |
|---------------|---------------------------------------------------------------|-----------------------------------------|
| **id**        | INT AUTO_INCREMENT PRIMARY KEY                                 |                                         |
| trx_type      | VARCHAR(30) NOT NULL                                           | e.g. `SOrlogo`, `SZardal`               |
| field_name    | VARCHAR(50) NOT NULL                                           | Column in target trx table              |
| label         | VARCHAR(80)                                                    | UI label                                |
| data_type     | ENUM('string','number','date','select','textarea') NOT NULL    | Input widget                            |
| editable      | TINYINT(1) DEFAULT 1                                           | 0 = read‑only                           |
| required      | TINYINT(1) DEFAULT 0                                           |                                         |
| lookup_table  | VARCHAR(50) NULL                                               | e.g. `items`, `accounts`                |
| lookup_label  | VARCHAR(50) NULL                                               | Which column to display in combobox     |
| default_value | VARCHAR(120) NULL                                              | Auto‑prefill                            |

**Rule:** if a field is *irrelevant* to a given transaction, it still exists in the schema but the UI marks it read‑only and stores `NULL/0/''` so the schema remains consistent.

### `schema.sql` migration
```
repo/
└─ db/
   └─ schema.sql   # canonical DDL script that creates all tables above
```
- Keep `schema.sql` inside the Git repo so the DDL is version‑controlled.
- First‑time deploy in GitHub Actions:
  ```bash
  mysql -u$DB_USER -p$DB_PASS $DB_NAME < db/schema.sql
  ```
- When the schema changes, append the proper `ALTER` statements, commit, tag with a semantic version (e.g. **v0.2**, **v0.3**), and deploy.
